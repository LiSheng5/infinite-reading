填写说明

下拉里带「生图」标注的服务商可直接选，地址会自动拼上 /images/generations。尺寸用「比例 + 宽高」自己定（比例选「自定义」即可手填）；不确定的项留空，会走通用默认。画师工作台里也能改尺寸。

MiniMax 原生接口：地址填 https://api.minimaxi.com（国内）或 https://api.minimax.io（国外），带不带 /v1 都行；模型填 image-01 或 image-01-live。MiniMax 不给浏览器跨域，直连被拦时先跑 node tools/video-proxy.mjs，地址改填 http://127.0.0.1:4320。
尺寸：image-01-live 只认比例，自定义宽高只对 image-01 生效（512–2048 且 8 的倍数）。画风只对 live 生效，写进「自定义请求参数」：style.style_type=漫画（漫画 / 元气 / 中世纪 / 水彩）+ style.style_weight=0.8（0–1）。想更稳再加 seed=12345。

参考图：开启后每次作画会把「上一张图」缩到长边 1024 的 JPEG，作为 subject_reference 交给接口，人物长相 / 服饰 / 画风更连贯，代价是构图更接近上一张。目前只有 MiniMax 原生适配器支持；第一次作画自动跳过。image-01-live 是否接受要实测，被拒会报 2013，改回「关闭」即可。

未启动

本地存储与备份

两种备份格式 · 数据存在哪 · 什么情况下会丢

.irbackup.json：全部故事 + 模型设置 + 用户画像，不含原图，体积可控。.zip：同一份正文 + 全部原图，换设备时连图一起搬。把文件拖回书架窗口即可整体还原（同 id 的故事会被覆盖，其它保留）。只想带走单个故事，用书架卡片上的「导出 → 附带原图」。

全部数据只存在这台设备的这个浏览器里（主库是 IndexedDB，原图以 Blob 单独存放），没有任何服务器。下列情况会让它消失：

· 清「Cookie 和网站数据 / 站点数据」会全删（只清缓存不受影响）
· 无痕 / 隐私模式，关窗即没
· 换浏览器、换设备、换打开方式（file:// 和 http://localhost 是两套独立数据）
· Safari（含 iOS）：7 天没和页面交互，系统会自动清除脚本可写存储，建议「添加到主屏幕」或常来点一下
· 磁盘空间紧张时，浏览器可能自动淘汰
