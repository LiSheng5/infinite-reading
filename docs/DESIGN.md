## 0. 一句话

v0.2 把两个 AI 的「记忆」和「用户对画面的控制权」做实：
**AI1 靠世界状态卡（自报 + 书记员校对）+ 按需召回抗遗忘，画师子代理靠视觉设定卡锚定画风与人物；提示词全透明可改，画师是可对话的子代理；聊天记录窗口推剧情，剧情/对话/角色扮演三种推进模式。**

## 2. 数据结构（story schema v2）

```js
story = {
  schema: 2,
  id, title, premise,
  mode: 'choice' | 'chat' | 'rp',  // R7+R13 推进模式，开局选定、可切换
  createdAt, updatedAt,

  log: [                          // 聊天记录主体，append-only
    { type: 'player'|'choice'|'narration'|'image'|'system'|'tool',
      text, ts, ... },
    // image 条目：{ id, prompt, promptRaw, alt, src?, thumb?, model,
    //               size, styleCardId, supersededBy? }
    // narration 条目：{ versions: [旧版本...], activeVersion }  ← R1 版本栈
    // tool 条目：{ tool: 'recall_world_state', summary }        ← T4 调用留痕
  ],

  world: {                        // R5 世界状态卡（AI1 自报 + 书记员校对 + 用户可改）
    place, time,
    characters: [{ name, presence, personality, speech, note }],  // 第七轮：加性格与说话方式（扮演一致性的关键）
    threads: ['伏笔...'],
    relationship: { stage, bonds, notes },  // R13 关系记忆（rp 模式为主；书记员随校对维护）
    scene: '画面参考一句话',
    updatedAt, scribeAt,          // 上次书记员校对时间
  },

  styleCard: {                    // R3 视觉设定卡
    id, version, locked,
    styleKeywords, palette, medium,
    characters: [{ name, appearanceEn, outfit, features }],
    negative, note,
  },
  rollingStyle: {                 // 第七轮：滚动风格摘要（每次出图后自动更新）
    style, scenes, wardrobe,      // 风格倾向 / 常见场景 / 人物服饰元素
    updatedAt,
  },

  characterCard: {                // R13 角色卡（rp 模式；兼容 SillyTavern V2/V3 导入）
    name, appearance, personality, scene,
    opening,                      // 开场白（首条旁白）
    exampleDialogue,              // 示例对话（喂给模型学口吻）
    systemNote,                   // 卡自带系统提示
    source: 'builtin' | 'st-import' | 'custom',
  },
  userProfile: [ { text, kind: 'fact'|'preference'|'taboo', updatedAt } ],
                                  // R13 用户画像（scope='per-story' 时在故事内；
                                  //   scope='global' 时存全局 ir:user-profile，见 §4.12）

  painterThread: [ { role, text, prompt?, ts } ],  // 画师工作台对话线程（第八轮：原 ai2Thread，画师降级为子代理后保留）
  messages: [...],                // AI1 原始对话（滑动窗口用）

  summaries: ['【第N幕】地点｜时间｜在场｜发生｜伏笔动作', ...],
                                  // C-A 场景摘要栈（§4.10 C-A；满则合并最旧两幕）
  savepoints: [ { id, name, ts, turn, log, world, styleCard, ... } ],
                                  // 手动存档点（§7；最多 5 个）
  styleTone: '',                  // 向导「风格基调」栏（§4.8；开局试画锚定的依据）
  ui: { split, showImage, immersive },
                                  // 界面状态随存档（§4.6 双栏比例 / 面板开合 / 沉浸态）
  // 随档的运行时字段：turn / scenes / lastBg / lastSceneSummary
}
```

设置项新增（settings）：
- **总原则（第九轮）**：所有模型一律**用户自选，并附推荐提示**（默认推荐最便宜/最合适的，用户可换任意对话模型）。
- `scribe: { enabled: true, every: 10, aiTasks: true, model 配置 }`——书记员模型，用户可配，默认推荐最便宜的（R5、第八轮）；`aiTasks` = 兼任压缩摘要 / 滚动风格摘要 / 画像提取，离线或关闭时走本地规则（T-P4-1 / T-P7-2）
- `painter: { model 配置 }`——画师子代理模型，用户可配（第八轮：取代原 AI2 配置；写提示词的隔离上下文调用）
- `draft: { model 配置 }`——开局向导「AI 起草」模型，用户可配，默认推荐剧情模型（第九轮）
- `userProfile: { enabled: { choice: false, chat: false, rp: false } | 'all', scope: 'global' | 'per-story' }`——用户画像（R13；第十一轮修订）：**默认全关**；用户可**按模式单独开或全开**；开启后范围用户自选（全局跨故事 / 仅当前故事）
- `image: { aspect: '16:9' | '9:16' | '1:1' | 'custom', width, height }`——替代单一 size 输入（R8）
- `showReasoning: true`——深度思考链是否展示（R9）
- `toolsEnabled: 'on' | 'off'`——第七轮 T3 定案后默认 on 直接下发、失败自动降级（§4.5），开关仅作手动兜底
- `noTools: [{ baseUrl, model }]`——被显式 400 拒绝 `tools` 的模型记录（§4.5 试错降级；设置面板可见可清，T-P5-1）
- **第八轮移除**：`ai2Follow` / `ai2.*`（AI2 独立配置区）——用户只配「剧情模型 + 画师子代理模型 + 书记员模型 + 生图模型」

## 3. 上下文组装

### 3.1 AI1 · 剧情对话

```
[system]  AI1_SYSTEM（JSON 输出规则 + world 自报规则 + 按模式的选项规则）
          ↳ choice 模式：强制「结尾必须给 2~3 个选项」
          ↳ chat 模式：不要求选项（给了也不渲染）
[system]  紧凑摘要行（固定格式，已确认）：
          「{地点}｜{时间}｜在场：{names}｜伏笔：{最重要的2条}」
[tools]   recall_world_state() / recall_style_card()（召回保留，第三轮确认）
          + request_image()（第七轮定，R13 起三种模式都带，见 §4.7/§4.8）
          + update_memory()（第十一轮：AI1 可直写世界卡 / 关系 / 画像，见 §4.1）
          ↳ 定义走 `tools` 参数结构化下发（JSON Schema + description），
            系统提示词只留 1~2 句调用策略（详见 §4.5）
            （不确定地点/时间/人物/前情/外貌时先调用再回答；玩家想看画面时调 request_image；
             玩家明确要求记住某事时调 update_memory）
[最近 8 条 messages]（4 个回合）
[user]    [玩家行动] …（premise 不再每轮携带，仅开局/召回/强制注入时进上下文）
```

### 3.2 画师子代理（第八轮：原 AI2，降级为内部实现）

```
[system]  PAINTER_SYSTEM（导演判断：画场景还是人物、构图、氛围）
[system]  视觉设定卡全文（锚，每次必带；未锚定时带滚动风格摘要代替，见 §4.10 C-F）
[context] 最近 2 张图的 prompt + alt（已确认：防重复即可，控制 token）
[context] 最近 3 条旁白
[tools]   recall_recent_plot() —— 仅画师工作台对话时可用，返回最近 10 条完整记录
[user]    [画面参考] world.scene ／ 工作台对话时为用户的话
```

- **隔离上下文**：子代理每次调用独立，用完即弃，不进 AI1 对话历史——AI1 只拿到「图画好了 + alt」；写提示词的中间过程不污染任何一方的上下文。
- 模型用户可配（`settings.painter`），默认最便宜。

> 注：喂给画师子代理的历史图是**文字提示词**（不是图片本身），只花对话 token，不耗生图额度；生图额度按「生成张数」计费，与上下文长短无关。

## 4. 关键机制

### 4.1 世界状态卡（R5，已确认）

- **自报**：AI1 每轮 JSON 带 `world` 字段（~50 token），解析失败沿用旧卡。
- **书记员校对**：每 10 回合（可配），用**便宜模型**（默认 glm-4-flash 级别，设置里可换任意对话模型）单独读最近剧情，重写整张卡——防止自报越写越偏。
- **用户可见可改**：世界卡面板在模型设置面板里（§4.9 归置原则），直接编辑字段，改完下轮生效；书记员校对不覆盖用户手改的 `note` 类字段。
- **AI1 可直接改记忆（第十一轮新增）**：AI1 带 `update_memory` 工具，可主动写世界卡/关系记忆/画像条目（如玩家明确说「记住我怕蜘蛛」）。写入即留痕（`tool` 条目），书记员照常校对兜底——自报、AI1 直写、书记员三路写同一张卡，书记员是最终仲裁。
- **第七轮确认：AI1 上下文快满时自动形成摘要**——不等爆满，达阈值（候选方案 C-C 的 ~70%）即由书记员产出**结构化 JSON 摘要**（当前人物/时间/地点/每个人物的性格与说话方式等），替换窗口最旧回合；自由文本摘要会越压越糊，必须结构化。

### 4.2 重试（R1，已确认）

- 最近一条旁白旁挂 ↻：取回最后玩家行动 + 附加「请换一种不同的发展」重发，**默认替换**，旧版进版本栈（≤5）。
- 「‹ 上一版」逐级回退，「下一版 ›」换回来；所有版本留在记录里。
- 图片重画：工作台同 prompt 重画（真实模型本身有随机性）。

### 4.3 提示词透明 + 画师工作台（R2/R8，已确认；第八轮：对话对象改为画师子代理）

- 每张图显示 alt，点开工作台：完整 prompt 可编辑、[按此重画]、与画师子代理对话线程（保留，用户第八轮选 A）——如「灯光暖一点」，子代理改 prompt。
- **出图参数**：比例（16:9 / 9:16 / 1:1 / 自定义）与分辨率在设置和工作台都可改，随请求传给适配器；个别服务商不支持时按报错提示调整（gpt-image-1 只接受三档固定尺寸等）。
- 试画引导的 4 张候选同样按用户选的比例出。

### 4.4 惰性记忆三层（R6，已确认）+ 记忆分模式（第十一轮定案）

三层机制（三模式共用）：

1. **常驻层**：固定格式摘要行，每轮必带（省钱的主体）。
2. **按需层**：`recall_world_state` / `recall_style_card` / `update_memory` 工具；**每次请求都带工具清单 + 系统提示词里写明调用时机**（用户调研的主流做法，采纳为唯一方案）；「客户端启发式注入」已按 C-E 提级（§4.10）并与工具召回并行落地。
3. **手动层**：「🧠 注入记忆」按钮放在模型设置面板（§4.9 归置原则）→ 当轮强制注入完整世界卡+设定+视觉卡并要求先复述处境再继续；图片侧「按设定卡强制重画」在画师工作台。

**记忆内容分模式（第十一轮用户定案）**——机制相同，记的东西不同：

| 模式 | 记什么 | 载体 |
|---|---|---|
| **choice 剧情** | 剧情记忆：发生了什么（地点/时间/人物/伏笔） | 世界卡（`place/time/characters/threads`） |
| **chat 对话** | 关系记忆 + 用户画像：我们之间发生了什么、你是个怎样的人 | 世界卡 `relationship` + `userProfile` |
| **rp 扮演** | 同 chat（**两者记忆系统完全一致**）+ 角色卡 | 同上 + `characterCard` |

- 剧情模式玩故事，记忆围绕**世界**；对话/扮演模式玩关系，记忆围绕**人与人的关系**。
- 世界卡结构三模式通用，只是各模式重点填的区块不同；书记员、压缩、召回机制完全复用。

### 4.5 工具治理（第七轮：T3 定案为试错降级；T2 流式规则修订）

- **下发方式（已定）**：主通道 = OpenAI 格式 `tools` 参数结构化下发（定义+JSON Schema 在 `tools`，说明在 `description`，调用时机一句话在系统提示词）；**不做提示词文本模拟工具的第二套机制**。（原「`tool_choice` 用于强制注入」已于第十六轮改定作废，见下。）
  - **⚠️ 实测修正 + 第十六轮改定**：DeepSeek-V4.1-Flash（思考模式默认开）实测 `tool_choice` 只接受 `auto` / `none`，传 `required` 或指定函数 → **400 `Thinking mode does not support this tool_choice`**。故「强制注入」**不再走 `tool_choice`**，改为：**客户端把完整世界卡 + 设定 + 视觉卡直接注入上下文，并在指令里要求「先用一两句复述当前处境（地点/时间/在场者/伏笔）再继续」**（不依赖任何厂商参数，跨模型一致，零额外往返）。
- 每轮最多 **2 次**工具调用，超出强制直接回答。
- 工具调用在聊天流里留痕（「📖 查阅了世界状态卡」「🎨 请画师作画」），延续透明思路。
- **流式规则（第七轮修订 T2）**：带工具也保持流式——OpenAI 兼容流式会以 delta 分片下发 `tool_calls`，思考链（`reasoning_content`）、工具调用、正文依次流式显示，全程可见（用户确认的 UX：等图期间对话先流式出来）。原「开工具关流式」作废。
- 无论流式与否，AI 回复出来前显示**「生成中…」**状态（对话气泡占位 + 作画 pill）。
- 模型返回 `reasoning_content`（深度思考）时，渲染为回答上方**可折叠的思考链块**，设置里可关（R9）。
  - **厂商约束（2026-10-05 官方文档 + 实测，T-P5-1/T-P5-2 实施必读）**：DeepSeek-V4.1-Flash（`deepseek-flash`）**思考默认开启**，思维链经 `delta.reasoning_content` 与 `content` 同层流式下发。文档要求「带 `tools` 时历史 `reasoning_content` 必须回传」，但实测（漏传、混传均试过）**未触发 400**，故本版不强制回传；真正会 400 的是另一条：**assistant 消息带 `tool_calls` 却没有跟随 `tool` 结果消息**（`insufficient tool messages following tool_calls message`）。因此召回类工具采用「单次重发」：**不把 `tool_calls` 写进历史**，客户端把召回内容作为系统块注入后重发一次（重发不带 `tools`）。
- **T3 定案（第七轮）：不做预探测，试错降级**——主流模型基本都支持 function calling；做法与开源 agent harness（LangChain / AutoGen / OpenAI Agents SDK）一致：直接带 `tools` 发，显式报 400 就记住该 `baseUrl+model` 并降级为无工具模式（思考链照常显示）；静默忽略的极端情形由设置开关 `toolsEnabled` 手动兜底。

### 4.6 剧情页交互：双栏布局（第七轮修订）

- **聊天窗口 : 画面展示 = 1:1 起步，分割条可拖拽调整**，比例随存档记住；拖到极端时自动吸附「画面为主/聊天为主」两档。移动端竖屏改上下堆叠，同样可拖。
- **画面面板**：当前大图 + 底部历史缩略条（点击回看）；将来的视频复用同一面板。
- **全屏沉浸第三态（保留）**：按钮一键收起聊天成底部浮动条，画面占满，看演出用。
- 聊天气泡流：玩家靠右、AI 旁白靠左、图片卡片、选项按钮内联在最新旁白下方、工具调用与重试留痕；输入框固定底部。

### 4.7 出图入口（第七轮修订：AI1 带 request_image 工具；R13 起三模式都给）

- **修订 T1**：原「不做 paint_scene 工具」决议部分作废——第七轮确认 AI1 带 `request_image` 工具（R13 起三种模式都给）。理由：对话模式下玩家说「画一张你的照片」，AI1 不能回答「我没有生图功能」（旁边画师明明在画图，体验割裂）。
- **工具不直连生图模型**：AI1 调用 `request_image` → 客户端转给画师子代理（第八轮：带视觉设定卡/滚动风格摘要写提示词 → 生图）→ 结果回传 AI1 → AI1 在回复里自然提到这张图。风格不漂移。
- **回合语义（用户确认）**：触发后**本回合等图出完再继续**（10~30 秒），期间对话先流式出来——思考链、工具调用、正文全程可见，显示「画师作画中…」，图作为卡片插入聊天流。
- **客户端入口保留**：出图时机**三种**（每轮对话后 / 做出选择后 / 仅手动；第十二轮砍掉「AI 判断 scene_change」——判断不稳、省不了多少）+ 「🎨 叫画师」按钮，与工具触发共用同一作画队列（顺序队列：当前回合对话与在途作画结束后才生成）。`scene_change` 字段保留，仅用于 C-A 压缩边界（§4.10）。
- **去重规则（第十一轮补缺口）**：AI1 工具已出图，则本轮的时机出图自动跳过——工具触发优先级最高，避免同轮画两张。
- **失败路径（第十一轮补缺口）**：作画失败时给 AI1 回传失败信息，让它在回复里自然圆场（不硬说「画好了」）；画师子代理模型未配置/失败时，兜底用场景描述直译英文送生图（跳过导演判断，保证出图不断）。
- 不做「全工具化 agent」：每轮 = 对话 + 提示词派发；唯一的子代理就是画师（第八轮），无更多层级。

### 4.7a 视频生成（第十一轮补缺口）

- **复用同一套触发时机与队列**，用户在设置/工作台选「出图 or 出视频」。
- **视频不同步等**：异步任务（提交 → 轮询），提交后显示「视频生成中…」，**对话继续**，完成后视频卡片插入聊天流、画面面板切换播放。图片等完（10~30 秒可接受），视频动辄几十秒到几分钟，不能卡回合。
- 适配器走已预留的 `VideoProviders`（可灵/Vidu 等，`generate(cfg, {prompt, image}) -> {url}`）。

### 4.8 三个推进模式（R7/R10/R13；第十轮扩为三模式）

- `story.mode`：**choice**（剧情）/ **chat**（对话）/ **rp**（角色扮演）。三者**都是 AI1 与用户自由对话、用户可随时直接输入文本**；区别只在提示词与渲染：
  - **choice**：结尾**给 2~3 个选项供点选，但用户随时可以自己打字**（选项只是辅助，不限制自由输入；第十二轮澄清），玩的是**故事**；
  - **chat**：不要求选项，自由聊天；
  - **rp**：带角色卡扮演（§4.12），玩的是**关系**；不要求选项。
- 三种模式都带 `request_image` 工具（§4.7）。
- 开局选定，设置里可切换；切换只改提示词与渲染，不影响记忆/重试/作画机制。
- **中途切换的边缘情况（第十一轮补缺口）**：切到 rp 时若没有角色卡 → 弹角色卡选择/新建；切出 rp 时角色卡保留在存档里（下次切回即用），只是停用；记忆数据不随切换清空（世界卡通用，见 §4.4）。
- **入口 = 书架直达，无开始界面（第十二轮定案）**：打开应用即进故事书架；「新故事」→ 选模式 → 进模式专属开局（向导/直接开聊/选角色卡）。模式选择与开局向导的 UI 实现自由发挥，遵循 §4.9 归置原则。
  - **第十四轮修订（用户定案）**：入口改回 v0.1 开始页（字体/简介/设定框原样），保留快通道「▶ 开始阅读」（用设定框直接开一局剧情）；本轮新增的「＋新故事 / ☰ 我的书架 / ⚙ 模型设置」放在同一排按钮里，书架降为第二页（「☰ 我的书架」「↶ 继续上次」进入）。
  - **第十九轮修订（用户定案，2026-10-07）**：开始页改版——**三个模式的介绍与选择直接放在首页**（三张模式卡，点一下选中：剧情 / 对话 / 扮演），按「开始」即按所选模式开局（剧情 = 设定框快通道、对话 = 直接开聊、扮演 = 弹角色卡），把「先选模式」这一步从弹窗挪到首页；只有剧情模式显示「故事设定」框（对话 / 扮演隐藏该框并给出对应说明）。同时删掉副标题「∞ READING…」、整段简介、标题旁朱砂「阅」印与副标题下的 ❦ 花饰，按钮「▶ 开始阅读」简化为「开始」（该按钮第二十轮取消，见下），删掉首页「＋新故事」（选模式弹窗保留在书架入口）。
  - **第二十轮修订（用户定案，2026-10-07）**：阅读页（三个模式共用）顶部 HUD 补齐出入口——左上「←」由「返回书架」改为**直接回首页**（玩完一局退出来即落回开始页，仍自动存档）；新增「☰ 书架」（进故事列表）与「＋ 新故事」（先把当前这一幕落盘，再开「新故事 → 选模式」弹窗，不必先绕书架）。即首页 ↔ 书架 ↔ 阅读页三方互通：任一模式在局内都能直接开新故事、翻书架或回首页（§7.1 同步）。
  - **第二十轮修订·续（用户定案，2026-10-07）**：开始页**去掉「开始」按钮**——**三张模式卡本身就是开局入口**，点哪张就按哪种模式开局（剧情 = 用「故事设定」框、对话 = 直接开聊、扮演 = 先建角色卡）。因此「故事设定」框**常驻显示**（不再随选中态显隐/高亮），只为剧情模式所用，常驻是为了点「剧情」卡时不至于无从填写。
  - **第二十轮修订·再续（用户定案，2026-10-07）**：开始页三张模式卡**只留「剧情 / 对话 / 扮演」三个词，卡面上的介绍文字全部去掉**（也不再有单独的说明行）；三个模式的介绍只保留在书架 / 阅读页「＋新故事」打开的选模式弹窗里。
- **剧情模式增加开局设定向导（R10；第九轮细节定案）**：
  - 分栏填写 世界观 / 主要人物 / 你的角色 / 风格基调 / 想看的发展（可选）（= 结构化 premise）；对话模式跳过向导直接开聊。
  - **向导同时初始化世界卡**：人物栏 → `world.characters`，世界观栏 → `place/time`——书记员第一次校对即有基线，AI1 自报有起点。
  - 「一句话让 AI 起草」：一次调用产出各栏草稿 → 用户在向导里改 → 确认；起草模型**用户自选、带推荐提示**（默认推荐剧情模型——起草需要创造力，不是书记员的校对活）。
  - **风格基调栏与试画锚定打通**：向导的风格基调直接喂给画师子代理，作为 4 组试画候选的生成依据（R10 定调子，R3 定具体画风）。
  - 模式切换：设置里随时切 choice / chat / rp（切到 rp 无卡、切出 rp 的边缘情况见本节第十一轮补缺口），只改提示词与渲染；已渲染的选项保留但不再强制。
- **表达期望（R11；第九轮细节定案）**：无独立机制——对局中玩家直接打字说「希望接下来…」，向导里则有可选栏；AI1 系统提示词写明「玩家可能表达对发展的期望，顺着编织、保持合理，不必生硬照办」。**不对称有意为之**：向导「想看的发展」栏写进 premise（常驻，故事地基）；对局中说的期望只随窗口自然淡出（一时之念）。

### 4.9 面板归置原则（第六轮确认）

- **硬规则：所有与模型相关的东西都归置进「模型设置」面板；游玩界面只留少数重要窗口，每个窗口用户都可以选择折叠或打开。**
- 游玩界面保留的窗口：聊天记录窗口（主交互）、画师工作台入口、世界卡/记忆入口（点开即进模型设置面板）。
- 归进模型设置面板的：世界状态卡编辑、摘要栈浏览、工具调用留痕、思考链、书记员配置、token 预算显示、强制注入按钮等——游玩时不叠在画面上。
- 各面板的折叠/展开状态随存档记住。

### 4.10 上下文策略深化（第十轮：C-A~C-E 全部认可确认）

- **C-A 压缩链与场景边界**：以 `scene_change` 为压缩边界做事件级摘要（一幕压一段），比固定每 N 回合压更连贯。场景摘要用固定槽位：`【第N幕】地点｜时间｜在场｜发生｜伏笔动作`；**伏笔显式标记「埋下/回收」**——世界卡 `threads` 管「有哪些伏笔」，摘要栈管「伏笔在哪一幕、什么状态」，两轨互证。摘要栈满时递归合并最旧两幕，越老越模糊；关键事实由世界卡无损兜底。
- **C-B 书记员双职**：每 10 回合（或满载触发时）一次便宜调用，同时做**校对 + 压缩**——输入 = 旧世界卡 + 待压缩原始回合，输出 = 重写后的世界卡 + 新场景摘要。合并省一次调用，且消除「原文已压缩、卡未更新」的空窗。输出显式 diff（事实变更/新埋伏笔/已回收伏笔），写入 `tool` 留痕条目，用户可见。
- **C-C Token 预算表 + 70% 阈值**：每段定预算（system ~150 / 常驻摘要行 ~60 / 世界卡 ~200 / 原文窗口 ~800 / 期望 ~100 / 画像注入 ~100），中文按 1 字 ≈ 1 token 估算；总和超模型容量 ~70% 即触发压缩（最旧窗口回合压进摘要栈 + 书记员顺带重写卡）。满载成为常态后台动作而非事故。（用户自有方案「满了自动形成摘要」已吸收为本条，第七轮定案）
- **C-D 评测先行**：mock 长局脚本埋 5 类探针（角色名/时间设定/伏笔原话/地点细节/玩家自己说过的事），每 10 回合插入追问回合判定命中率，作为上下文策略改动的量化分数；先测组装/压缩逻辑本身，不花 API。
- **C-E 启发式注入提级**：把「客户端启发式注入」从 backlog 提为与工具召回并行的兜底——玩家输入出现世界卡/伏笔中的实体词就自动注入对应条目；成本极低，且正好覆盖 T3 最麻烦的「静默忽略工具」情形。
- **C-F 滚动风格摘要（第七轮新增）**：每次出图后自动更新 `rollingStyle`（风格倾向/常见场景/人物服饰元素），画师子代理每轮带着。视觉设定卡 = 手动锁定版，滚动摘要 = 自动版；有卡时卡优先，跳过开局锚定也不漂移。

### 4.11 剧情导入与分享（R12，无市场；第九轮细节定案）

- **原则**：不做市场、不做服务器——分享即传文件，导入即本地建档；导入内容的合规与质量由分享者负责。
- **导出（书架）**：`.irstory.json` = { schema, title, premise, world?, styleCard?, rollingStyle?, mode, opening?: 若干条开局 log, images?: 若干画风图 }；作者可选「完整档案」（含全量 log，别人可原样续玩）或「精简设定包」（只有开局材料）。
- **图片策略（第九轮）**：导出默认只带**缩略图 + prompt**（文件小），可选带原图；导入后缺原图的场景可「按原 prompt 重画」恢复。
- **导入路径① 档案直入**：拖进窗口/选文件 → 进书架；完整档案原样续玩（messages / world / styleCard 原样恢复），精简包用导入的 premise 预填开局向导 → 走正常开局流程（试画锚定 → 开场）。
- **导入图片的画风参考（第九轮现实约束）**：画师子代理是文本模型看不了图，图生图在 v0.3 backlog——所以导入图片只在书架当「画风参考展示」，实际锚定仍走试画；若用户的剧情模型恰好多模态（如 gpt-4o），可顺手让它看图提取风格关键词填进向导。不做重。
- **导入路径② 文本压缩整理**：粘贴任意剧情文本（设定文/小说片段/别人游戏的聊天记录）→ 整理向导调用（**模型用户自选、带推荐提示**）→ 产出 premise + world 卡草稿 + 画风关键词 → 用户确认修改 → 建新档 → 走开局试画锚定出画风候选图。
  - **长文处理（第九轮）**：默认一次调用；**当所选模型装不下该文本时才启用 map-reduce**——分段各出摘要，再一次合并成 premise + world 草稿 + 画风关键词。
  - **整理模型显式化（第十九轮用户定案）**：弹窗内直接选「跟随剧情模型（默认）/ 起草模型（模型设置里单独配的那个）/ 离线演示」，不在设置里新增项；提示行与确认页都写明当前用的模型与来源（`xxx（跟随剧情模型）` / `xxx（起草模型）` / `离线演示`）——此前只显示一个模型名，容易被当成硬编码。
- **安全边界**：导入的 premise 是他人文本、会注入模型；流程中的「用户确认修改」一步不可跳过，即人肉过滤，不做额外防护。
- 导入的剧情与原生玩法完全一致：选项点按或直接打字，无特殊通道。

### 4.12 角色扮演模式（R13，第十轮新增）

- **定位**：独立第三模式（用户拍板，不做成 chat 的开关）。剧情模式玩故事，rp 模式玩关系。
- **角色卡**：
  - 字段：名字/外貌/性格/场景/开场白/示例对话/系统提示（§2 `characterCard`）。
  - **兼容 SillyTavern V2/V3 角色卡导入**（用户确认）——PNG 内嵌 JSON 直接解析。
  - **合规注意（用户强调）**：只兼容**格式**，不复制其代码与内容；实现时确认所用规范无协议问题（V2/V3 卡格式为社区通用数据格式，导入用户自己的卡不涉及复制他人作品）。
  - 导入角色卡 = 初始化世界卡对应角色条目（personality/speech 天然对接）。
  - **角色卡可编辑（第十一轮补缺口）**：统一编辑器——自建卡 = 空白表单填写；导入卡 = 导入后可编辑；改完即生效。
- **关系记忆**：世界卡加 `relationship`（stage/bonds/notes）区块，书记员随校对维护——剧情记忆记「发生了什么」，关系记忆记「我们之间发生了什么」。
- **用户画像（重点机制）**：
  - **开关与范围（用户拍板）**：默认**关闭**；开启后范围用户自选——`global`（跨故事共享，存全局 `ir:user-profile`）/ `per-story`（仅当前故事）。**chat 模式同样适用**，不只 rp。
  - **提取**：书记员兼任——校对世界卡时顺手判断「本轮有没有值得记住的用户信息」，产出结构化条目（fact/preference/taboo）。思路参考 Mem0（LLM 抽取事实→去重→更新），机制自建。
  - **防 token 爆炸（关键设计）**：画像**不常驻、不全量注入**——① 存储无上限，注入有预算：每轮只注入与当前话题相关的 Top-N 条（客户端按关键词匹配选条，即 C-E 启发式的复用）；② 常驻只有一行画像摘要（~30 tok）；③ 条目定期合并去重（书记员顺手做），同类信息只留最新。画像记一万条，每轮注入也不超过预算。
  - **用户可见可删**：画像面板在模型设置里（归置原则），每条可单独删除；关闭开关即停止收集（已存条目保留，可手动清空）。

### 4.13 模型能力参数注册（第十三轮定案：按各家官方文档）

- **原则**：各家模型的可选参数差异极大（思考档位、图片尺寸、视频帧率/时长、上下文窗口），**不硬编码**——`js/modelCapabilities.js` 只是一张**默认留空**的能力登记表（结构与查询逻辑保留，可用于按需预填）；请求参数只发该模型支持的字段，不支持的静默不发（与 §4.5 T3 试错降级同思路）。
- **登记表字段**（每个模型条目）：
  - `contextWindow`：上下文窗口大小（token）——**70% 压缩阈值按它算**（§4.10 C-C），未登记的模型由用户在设置里手填容量；
  - `thinking`：思考档位支持（无 / 开关 / 档位），如 DeepSeek `reasoning_effort: low|medium|high`、GLM `thinking: {type}`、OpenAI o 系 `reasoning_effort`；
  - `image`：支持的尺寸枚举、质量档、响应格式（url/b64）——如 gpt-image-1 只收三档固定尺寸；
  - `video`：分辨率/帧率/时长档位（可灵 5s|10s、mode std|pro；Vidu 4s|8s 等）。
- **UI**：模型设置面板里，选中某模型后**只显示它支持的参数**（归置原则 §4.9）；参数值以登记表为准，登记表缺的模型允许用户手填。
- **维护**：登记表是纯数据文件，新增模型 = 加一条数据，不动逻辑。
  - **第十七轮修订（用户定案）**：**不预置任何模型数据**——登记表默认留空，设置面板不再提供「快速填充」服务商预设（原预设同时填地址 + 模型名，模型名需持续维护）。现改为：**只给 Base URL 一个原生 `datalist` 下拉**（国内外 / 本地常见服务商接口地址，可选可手填），**不预置任何模型名**——地址稳定、几乎不用维护，模型名与厂商参数由用户手填。手填通道：设置里的「自定义请求参数」（`key=value` 原样并入请求体，支持 `a.b` 嵌套）与「比例 + 宽高」（比例选自定义即手填）；适配器接口（`providers.js`）才是唯一硬约定。

## 7. 存储与数据安全（R4 已确认；第十二轮加存档点；第十八轮补数据安全）

### 7.1 存哪、存什么

- 介质：**只有 localStorage**（前缀 `ir:`），没有服务端、没有云：`ir:settings` / `ir:story-index` / `ir:story:<id>` / `ir:current` / `ir:user-profile`。
- 每个故事 = 一份聊天记录（`ir:story:<id>`），含完整 log、world、styleCard、painterThread、mode。
- **故事书架**：标题/最后游玩/缩略图，可继续/改名/删除/导出 JSON。**书架即应用入口，无开始界面**（第十二轮；**第十四轮修订：入口回到开始页，书架经「☰ 我的书架 / ↶ 继续上次」进入**；**第十九轮：开始页直接用三张模式卡开局，「＋新故事 → 选模式弹窗」只留在书架**；**第二十轮：阅读页 HUD 也放了「☰ 书架 / ＋新故事」，左上「←」改为回首页——三个模式在局内就能直接开新故事或翻书架**）。
- **存档（第十二轮定案）**：退出即自动存档；另有**手动存档点**——用户随时点「存档」打一个具名存档点，可随时**回到**任一存档点（恢复到该点的 log/world/画面）。存档点列表在模型设置面板里（归置原则）。
- **体积控制**（因为 localStorage 每站点只有约 **5MB**）：`serializeStory` 只留最近 120 条 log、最近 12 幕；图片只留**缩略图**（长边 560px JPEG），存档点里剥掉全尺寸 `src`；单故事最多 5 个存档点。
- 导出格式：单故事 `.irstory.json`（可分享/重玩，`kind = full | premise`）；**整体备份 `.irbackup.json`**（第十八轮新增：全部故事 + 设置 + 画像，可整体还原），**带原图的整体备份 `.irbackup.zip`**（v0.3.0 新增：同上正文 + `images/*` 二进制原图，勾选后导出）。
- 聊天记录窗口为主交互（§4.6）。

### 7.2 什么情况下会丢（已写进设置面板告知用户）

| 操作 / 情况 | 结果 |
|---|---|
| 清「缓存 / 缓存的图片和文件」 | **不影响**（localStorage 不属于缓存） |
| 清「Cookie 和网站数据 / 站点数据」 | 全部删除，且无提示 |
| 无痕 / 隐私模式关窗 | 删除 |
| 换浏览器 / 换设备 | 各浏览器、各设备独立，彼此看不到 |
| 换打开方式（`file://` ⇄ `http://localhost`） | **两个不同 origin，数据互不相通** |
| Safari（含 iOS）：7 天未与页面交互 | ITP 自动清除脚本可写存储（含 localStorage / IndexedDB）；服务器 Cookie 豁免。加到主屏幕或保持交互可避免 |
| 磁盘空间紧张（best-effort origin） | 可能被 LRU 淘汰（`persist()` 获批则跳过） |

### 7.3 浏览器机制要点（据 MDN「Storage quotas and eviction criteria」，2026-01 更新）

- **配额**：Web Storage（localStorage + sessionStorage）每 origin 合计约 **10 MiB**（localStorage ≈ 5 MiB）；IndexedDB / Cache / OPFS 大得多——Chrome 约磁盘 60%，Firefox best-effort 取 min(磁盘 10%, 10 GiB)、persistent 可达磁盘 50%。
- **淘汰（eviction）**：在存储压力、或浏览器总配额超限时按 **LRU** 清除，且**跳过已获 `navigator.storage.persist()` 授权的 origin**；被淘汰时该 origin 的数据**整体清除**（不做部分保留）。Safari 另有「7 天无交互主动清理」。Chrome 团队调研：实际被浏览器删掉的情况**极罕见**。
- **持久化**：`navigator.storage.persist()` → Firefox 弹窗询问，Chromium / Safari 按站点交互历史自动判定；获批后只有用户手动删除才会消失。**注意豁免范围是 Storage API 管的存储（IndexedDB / Cache / OPFS）；localStorage 属 Web Storage，不在其明确保障内**——要真正吃到豁免需迁到 IndexedDB（§7.5 P1）。

### 7.4 同类开源项目怎么做（第十八轮调研，只借鉴思路）

| 项目 | 本地存储 | 备份 / 同步 |
|---|---|---|
| SillyTavern | Node 服务端，聊天存服务器磁盘 JSON（`data/…/chats/`），角色卡为 PNG | 导出 JSON/JSONL；用户自行备份 `data/` 目录 |
| RisuAI | `localforage` → **IndexedDB**（高性能走 OPFS），桌面走 Tauri 文件系统 | 自研 `.risudat` 二进制（msgpack + 压缩 + 分块增量）；Google Drive 备份；桌面版**轮转备份**（主档坏了自动回退）；云同步冲突**交用户显式二选一**；旧历史进「冷存储」压缩外置 |
| NextChat (ChatGPT-Next-Web) | IndexedDB / localStorage | 一键导出导入 JSON；**Cloud Sync 到 Upstash Redis / WebDAV（坚果云）** |
| Open WebUI | 服务端 **SQLite**（`webui.db`），前端另用 IndexedDB 做离线缓存 | 导入/导出整个数据库、单对话导出 |
| LibreChat | 服务端 **MongoDB** | 数据库级备份 |
| Jan / Chatbox | 桌面 App，本地文件系统 / 本地数据库 | 备份数据目录、可选云同步 |
| LobeChat | 本地模式 **IndexedDB（Dexie）**；服务端版 Postgres | 导入导出 |

归纳五条通用做法：① 主库用 **IndexedDB**（大容量、可持久化），图片等大文件另走 OPFS / File System Access API——**没人拿 localStorage 当主库**；② 启动即申请 `persist()`；③ 本地优先 + **可选**云同步（WebDAV / 网盘 / 自建），冲突交用户选，不静默合并；④ 导出/导入是**一等公民**，配合自动 / 轮转备份；⑤ 大文件外置 + 冷存储。
